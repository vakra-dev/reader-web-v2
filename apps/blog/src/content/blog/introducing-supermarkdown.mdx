Supermarkdown is an HTML to markdown conversion engine built from scratch in Rust. It converts HTML to GitHub Flavored Markdown in a single pass with browser grade error recovery, and it is designed specifically for web scraping and LLM pipelines where speed and accuracy both matter.

Available as a Rust crate, npm package (via napi-rs native bindings), and CLI tool. MIT licensed, open source at [supermarkdown.dev](https://supermarkdown.dev).

## Why We Built It

Existing HTML to markdown converters fall into two categories. JavaScript libraries like Turndown.js are popular and well maintained but become bottlenecks at scale. Python libraries like markdownify and html2text are convenient but lack robust handling of malformed HTML. Neither category was built for the demands of production web scraping.

Web scraping pipelines process thousands to millions of pages per day. At that scale, conversion speed directly affects throughput. A converter that takes 50ms per page means 14 hours to process a million pages. A converter that takes 5ms means 83 minutes.

Real world web HTML is also messy. Pages from content management systems have unclosed tags, incorrectly nested elements, and markup that would not pass any validator. Most converters either crash on malformed HTML or produce garbled output. In a pipeline processing arbitrary URLs, you need a converter that handles whatever the web throws at it without breaking.

We needed both: speed for throughput and robustness for reliability. So we wrote Supermarkdown in Rust.

## Architecture

### HTML Parsing with html5ever

Supermarkdown uses html5ever for HTML parsing. html5ever is the same parser that Firefox uses, implementing the WHATWG HTML specification's error recovery algorithm. When it encounters malformed HTML (missing closing tags, incorrectly nested elements, invalid attribute values), it recovers in the same way a browser would. The parsed DOM matches what a real browser would render, even from broken input.

This is the foundation that makes Supermarkdown reliable on arbitrary web content. Other converters that use simple regex or basic DOM parsers fail on the same input that html5ever handles gracefully.

### Single Pass O(n) Conversion

The conversion algorithm walks the DOM exactly once. In that single pass, it pre computes all metadata: list indices and nesting levels, CSS selector match results, heading levels, and code block nesting depths. This metadata is stored in a flat lookup table.

A second pass converts the DOM to markdown using O(1) lookups against the pre computed metadata. There is no intermediate AST, no multi pass transformation, and no recursive descent. HTML goes in, markdown comes out.

### Zero Copy and No GC

Rust's ownership model enables two properties that matter for pipeline performance.

Zero copy where possible. Strings are borrowed from the parsed DOM rather than cloned, reducing memory allocation. For large pages, this reduces both memory usage and allocation overhead.

No garbage collector. Unlike JavaScript (V8 GC) or Python (reference counting + cycle collector), Rust has no runtime garbage collection. Memory is freed deterministically when values go out of scope. This means no GC pauses, no unpredictable latency spikes, and consistent throughput under load.

For a pipeline processing pages continuously, predictable latency matters more than peak throughput. You need every conversion to complete in roughly the same time, not most conversions to be fast with occasional 100ms pauses while the garbage collector runs.

## What It Handles

### Tables

Full GFM table support with alignment detection. Supermarkdown reads the `align` attribute and the `text-align` CSS property to determine column alignment (left, center, right). The first row automatically becomes the header row.

Markdown has no syntax for colspan, rowspan, or nested tables. Supermarkdown handles these gracefully: colspan content is placed in the first cell, and nested tables are flattened into the parent table. These are deliberate degradations rather than crashes.

### Code Blocks

Fenced code blocks with automatic language detection. Supermarkdown reads class patterns on `<code>` and `<pre>` elements: `language-python`, `lang-js`, `highlight-rust`, `hljs-go`, and similar patterns used by syntax highlighting libraries.

Line numbers from syntax highlighted code (common in documentation sites and code sharing platforms) are automatically stripped. The output contains only the code itself.

Dynamic backtick fencing handles code content that contains backticks. If the code uses triple backticks, Supermarkdown wraps it in quadruple backticks. This prevents the common problem of code blocks breaking when they contain markdown code fences.

### Lists

Deeply nested lists with correct indentation at every level. Ordered lists preserve the `start` attribute (e.g., a list starting at 5 renders as `5.`, `6.`, `7.`). Task lists with checkboxes are converted to GFM task list syntax (`- [ ]` and `- [x]`). Definition lists (dt/dd elements) are also supported.

### Links and URLs

Configurable link style: inline (`[text](url)`) or reference (`[text][1]` with references at the bottom). The `baseUrl` option resolves relative URLs to absolute, which is essential for web scraping where pages reference resources with relative paths. Spaces and parentheses in URLs are percent encoded automatically to produce valid markdown links.

### Other Elements

Strikethrough, autolinks, horizontal rules, blockquotes (including deeply nested), images with alt text, details/summary elements, and heading style (configurable between ATX with `#` markers or Setext with underlines).

## Content Filtering

Supermarkdown can extract main content during conversion through CSS selector filtering, eliminating the need for a separate content extraction step.

```javascript
import { convert } from '@vakra-dev/supermarkdown';

const markdown = convert(html, {
  excludeSelectors: ['nav', 'header', 'footer', '.sidebar', '.ad', '.cookie-banner'],
  includeSelectors: ['article', 'main', '.content']
});
```

`excludeSelectors` skips elements matching those CSS selectors during traversal. `includeSelectors` processes only elements matching those selectors. When both are used, includeSelectors takes priority: only matching elements are processed, and excludeSelectors removes sub elements within them.

This is a single pass operation. The selector matching happens during the same DOM traversal as the markdown conversion, not as a separate preprocessing step.

## How to Use It

### Node.js

```bash
npm install @vakra-dev/supermarkdown
```

```javascript
import { convert, convertAsync } from '@vakra-dev/supermarkdown';

// Synchronous
const markdown = convert(html, {
  baseUrl: 'https://example.com',
  excludeSelectors: ['nav', '.footer'],
  codeBlockStyle: 'fenced',
  bulletListMarker: '-'
});

// Async (for large documents, non-blocking)
const markdown = await convertAsync(html, options);
```

Prebuilt native binaries are available for Windows, macOS, and Linux on both x64 and ARM64 architectures. No Rust toolchain required for npm installation.

### Rust

```bash
cargo add supermarkdown
```

```rust
use supermarkdown::{convert, Options};

let options = Options {
    base_url: Some("https://example.com".into()),
    ..Default::default()
};
let markdown = convert(html, Some(options));
```

### CLI

```bash
cargo install supermarkdown-cli

# Convert a file
supermarkdown input.html

# Pipe from curl
curl -s https://example.com | supermarkdown

# With options
supermarkdown --base-url https://example.com --exclude-selectors "nav,.footer" input.html
```

The CLI supports stdin piping, making it composable with other command line tools. Fetch a page with curl, pipe it through Supermarkdown, and redirect the output to a file or another program.

## How Reader Uses Supermarkdown

Reader's scraping pipeline works in stages: fetch the page with a headless browser, render JavaScript, run content extraction, and convert with Supermarkdown. The `excludeSelectors` and `includeSelectors` options are configured during conversion to strip navigation, ads, and boilerplate in the same pass as the structural conversion.

Reader's README describes the relationship: "Reader uses supermarkdown for HTML to Markdown conversion, a sister project we built from scratch specifically for web scraping and LLM pipelines."

Supermarkdown is a standalone library with no dependency on Reader. You can use it independently in your own projects for any HTML to markdown conversion task.

## Conclusion

Supermarkdown exists because web scraping at scale demands a converter that is both fast and robust. The combination of Rust performance, html5ever parsing, single pass conversion, and CSS selector filtering produces clean GFM output from arbitrary web HTML without crashes, garbled output, or unpredictable latency.

It is MIT licensed, available as a Rust crate and npm package, and open source at [supermarkdown.dev](https://supermarkdown.dev). Source code is on [GitHub](https://github.com/vakra-dev/supermarkdown).
