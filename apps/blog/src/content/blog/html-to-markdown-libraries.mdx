HTML to markdown conversion sounds simple until you hit nested tables, malformed HTML, code blocks containing backticks, or content mangled by a dozen layers of CMS templating. The right library depends on your language, your performance requirements, and how messy your HTML sources are.

This guide compares the most actively used libraries across JavaScript, Python, Rust, and Go, with assessments of what each handles well and where each breaks.

## What Makes a Good Converter

Six criteria separate good converters from adequate ones.

**GFM support.** GitHub Flavored Markdown is the de facto standard for developer tooling. Tables with alignment, fenced code blocks with language identifiers, task lists, and strikethrough are all expected in modern markdown output.

**Malformed HTML handling.** Real world web HTML is messy. CMS systems generate unclosed tags, incorrectly nested elements, and invalid attributes. A converter that crashes or produces garbled output on bad HTML is unusable for web scraping.

**Performance.** For single documents, every converter is fast enough. For pipelines processing thousands or millions of pages, conversion speed directly affects throughput. A 10x difference in speed means the difference between processing a million pages in 83 minutes versus 14 hours.

**Content extraction.** Some converters can identify and extract the main content from a page, skipping navigation, ads, and boilerplate. Others convert everything in the DOM, including all the noise.

**Extensibility.** Custom rules, plugins, and configuration options let you adapt the converter to specific HTML patterns in your data.

**Active maintenance.** Libraries that have not been updated in years may not handle modern HTML patterns or newer GFM features.

## Turndown.js (JavaScript)

Turndown.js is the most widely used HTML to markdown converter in any language. It has over 11,000 GitHub stars, more than 3 million weekly npm downloads, and is licensed under MIT. It powers Jina Reader's conversion pipeline and is used by countless web clippers, content management systems, and developer tools.

Turndown works in both Node.js and browser environments. It converts HTML elements to markdown through a rule based system where each HTML element type has a corresponding conversion rule. The architecture is plugin extensible: you define custom rules for elements that need special handling.

GFM support is available through the `turndown-plugin-gfm` package, which adds tables, strikethrough, and task lists. Without the plugin, Turndown produces standard CommonMark.

```javascript
const TurndownService = require('turndown');
const { gfm } = require('turndown-plugin-gfm');

const turndownService = new TurndownService();
turndownService.use(gfm);

const markdown = turndownService.turndown(html);
```

**Strengths:** Largest ecosystem, excellent documentation, plugin extensible, works in browser and Node.js.

**Limitations:** No malformed HTML recovery (assumes valid HTML input). No content extraction (converts everything in the DOM). Performance is adequate for individual documents but becomes a bottleneck at scale due to JavaScript's single threaded execution model.

## markdownify (Python)

markdownify is the most actively maintained Python HTML to markdown library. It is MIT licensed with frequent releases that add features and fix edge cases. Recent versions include definition list support, table header inference via the `table_infer_header` option, and improved heading blank line handling.

markdownify handles nested lists more accurately than html2text and produces cleaner table output. It also has a Go port (go-markdownify) for teams that work across both languages.

```python
from markdownify import markdownify as md

html = """
<h1>Title</h1>
<p>A paragraph with <strong>bold</strong> and <em>italic</em>.</p>
<ul>
  <li>Item 1
    <ul><li>Nested item</li></ul>
  </li>
  <li>Item 2</li>
</ul>
"""

markdown = md(html)
```

**Strengths:** Best Python option for accuracy, actively maintained, good nested list and table handling, Go port available.

**Limitations:** No malformed HTML recovery, no content extraction, no JavaScript rendering. Converts whatever HTML string you pass in.

## html2text (Python)

html2text was originally created by Aaron Swartz. It produces readable plaintext with markdown style formatting. It is lighter and faster than markdownify, with options to ignore links, images, and tables.

```python
import html2text

converter = html2text.HTML2Text()
converter.body_width = 0
converter.ignore_links = False
converter.ignore_images = True

markdown = converter.handle(html)
```

**Strengths:** Lightweight, fast, good for "make this readable" use cases. Simple API.

**Limitations:** Weaker on complex nested structures compared to markdownify. Table handling is basic. Better suited for plaintext extraction than strict GFM compliance.

## Pandoc (Haskell)

Pandoc is the universal document converter, handling dozens of input and output formats. For HTML to markdown specifically, `pandoc -f html -t gfm` produces the most edge case correct output of any converter. It handles nested tables, definition lists, footnotes, and deeply nested structures that break every other tool.

**Strengths:** Best edge case handling in the ecosystem. Handles the widest range of HTML patterns. Mature and thoroughly tested.

**Limitations:** System binary, not a library you import. Not practical for serverless, browser, or embedded environments. Converts the entire document including navigation and boilerplate because it has no concept of content extraction.

## Supermarkdown (Rust)

Supermarkdown is built specifically for web scraping and LLM pipelines. It uses html5ever (the same parser Firefox uses) for browser grade malformed HTML recovery and performs a single pass O(n) DOM traversal with pre computed metadata for O(1) lookups during conversion.

Full GFM support is native, not via plugins: tables with alignment detection, fenced code blocks with language detection (reads `language-*`, `lang-*`, `highlight-*`, `hljs-*` class patterns), task lists, strikethrough, definition lists, and details/summary elements. Dynamic backtick fencing handles code that contains backticks. Automatic line number stripping removes syntax highlighting artifacts.

A standout feature is CSS selector filtering. The `excludeSelectors` and `includeSelectors` options enable content extraction during the same conversion pass, eliminating the need for a separate Readability step.

```javascript
import { convert } from '@vakra-dev/supermarkdown';

const markdown = convert(html, {
  baseUrl: 'https://example.com',
  excludeSelectors: ['nav', '.sidebar', '.footer', '.ad'],
  codeBlockStyle: 'fenced'
});
```

```rust
use supermarkdown::{convert, Options};

let options = Options {
    base_url: Some("https://example.com".into()),
    ..Default::default()
};
let markdown = convert(html, Some(options));
```

Available as a Rust crate (`supermarkdown` on crates.io), npm package (`@vakra-dev/supermarkdown` via napi-rs with prebuilt binaries), and CLI tool. MIT license. Used inside Reader for all HTML to markdown conversion.

**Strengths:** Browser grade malformed HTML recovery via html5ever, single pass performance, native GFM, CSS selector content filtering, available in Rust and Node.js.

**Limitations:** Newer project (v0.0.6) with a smaller community than Turndown.

## html-to-markdown (Go)

JohannesKaufmann's html-to-markdown v2 is the standard Go library for HTML to markdown conversion. It uses a plugin based architecture with commonmark, base, and table plugins. CLI binaries are available via GoReleaser.

```go
import "github.com/JohannesKaufmann/html-to-markdown/v2"

markdown, err := htmltomarkdown.ConvertString(html)
```

**Strengths:** Well designed plugin architecture, actively maintained, CLI available, good for Go pipelines.

**Limitations:** Go only (no bindings for other languages). Community smaller than Turndown.

## html-to-markdown-rs (Rust)

The html-to-markdown-rs crate (v3.5.7) is an established Rust option with over 477,000 all time crate downloads and bindings for 16 languages. It uses a three tier dispatch system: byte scanner for simple HTML, DOM walker for structured content, and html5ever repair for malformed input.

It supports CommonMark and Djot output formats and includes metadata extraction. The polyglot bindings make it accessible from Python, JavaScript, Ruby, Go, and many other languages.

**Strengths:** Most mature Rust option by download count, 16 language bindings, three tier dispatch for optimal performance, metadata extraction.

**Limitations:** Does not produce GFM specifically (CommonMark and Djot). No CSS selector content filtering.

## node-html-markdown (JavaScript)

node-html-markdown takes a streaming tokenizer approach rather than DOM based conversion. It has roughly 333,000 weekly npm downloads and is faster than Turndown on large documents because it processes HTML as a stream rather than building a full DOM tree first.

**Strengths:** Faster than Turndown on large documents, streaming architecture, good for high volume processing in Node.js.

**Limitations:** Fewer custom rules and plugins than Turndown. Smaller community.

## ReaderLM v2 (Neural)

ReaderLM v2 is a fundamentally different approach. Built by Jina AI, it is a 1.5 billion parameter language model (based on Qwen2.5 1.5B Instruct) that converts HTML to markdown using AI rather than rules.

It handles up to 512K combined input and output tokens, supports 29 languages, and achieves a ROUGE L score of 0.84 on main content extraction. The model is Apache 2.0 licensed on HuggingFace and remains available after Elastic completed its acquisition of Jina AI in October 2025.

**Strengths:** Handles ambiguous and inconsistent content better than any rule based converter. Built in content extraction. Multilingual.

**Limitations:** Requires GPU inference (~67 tokens/s in, ~36 tokens/s out on a T4). Orders of magnitude slower than rule based converters. Not practical for high volume pipelines.

## Which Library to Use

**JavaScript project, need customization:** Turndown.js. Largest ecosystem, most plugins, works in browser and Node.js.

**JavaScript project, need speed on large documents:** node-html-markdown. Streaming tokenizer is faster than Turndown's DOM approach.

**Python project:** markdownify. Best balance of accuracy, features, and active maintenance.

**Go project:** html-to-markdown. Well designed plugin architecture, actively maintained.

**Rust project or need maximum performance:** Supermarkdown. Single pass conversion, html5ever parsing, native GFM, CSS selector filtering.

**Need polyglot bindings:** html-to-markdown-rs. Bindings for 16 languages from a single Rust core.

**Need to handle any document format:** Pandoc. Nothing else matches its breadth.

**Need AI powered conversion for ambiguous content:** ReaderLM v2. Fundamentally different approach that handles content extraction and conversion in one model call.

**Need end to end web scraping plus conversion:** Reader. Uses Supermarkdown under the hood and handles fetching, JavaScript rendering, anti bot bypass, and content extraction in a single API call. 1,000 free pages per month at [reader.dev](https://reader.dev).

## Conclusion

The HTML to markdown converter you choose depends on three factors: your programming language, your tolerance for malformed HTML, and whether you need content extraction alongside conversion.

For most JavaScript projects, Turndown.js remains the default. For Python, markdownify. For Rust or high performance pipelines, Supermarkdown combines speed, robustness, and content filtering in a single pass. For the full pipeline from URL to clean markdown, Reader handles everything.
