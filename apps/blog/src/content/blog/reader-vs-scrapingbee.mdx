ScrapingBee is one of the most established web scraping APIs on the market. It has been around since 2019 and is now part of the Oxylabs group. Reader is a newer, open source alternative that takes a fundamentally different approach to web infrastructure for AI.

This comparison covers features, open source licensing, browser automation, output quality, and anti bot performance so you can decide which fits your workload.

## What ScrapingBee Does

ScrapingBee is a fully managed web scraping API. You send it a URL, it handles JavaScript rendering, proxy rotation, and anti bot bypass, and returns the page content. It has been serving developers since 2019 and has grown to over 2,500 customers.

Beyond basic scraping, ScrapingBee offers dedicated APIs for specific platforms. The Google Search API returns structured SERP data. The Amazon API handles product pages, reviews, and search results. There are also dedicated endpoints for Walmart, YouTube, and ChatGPT. These site specific APIs are purpose built for those platforms and handle their unique anti bot measures and page structures.

ScrapingBee also includes an AI Query feature that lets you extract structured data using natural language prompts. JavaScript scenarios allow you to click, scroll, type, and execute custom JavaScript before the page content is extracted. This is useful for dismissing cookie banners, loading dynamic content, or interacting with page elements.

SDKs are available for Python and JavaScript. No code integrations work with n8n and Make. ScrapingBee also offers an MCP server for AI coding tools like Claude Code and Cursor, exposing scraping and site specific API tools through the Model Context Protocol.

## What Reader Does

Reader is an open source web infrastructure platform built for the AI era. It is licensed under Apache 2.0 and the entire platform is available on GitHub. You can self host it on your own infrastructure or use the managed cloud platform at reader.dev.

Reader is built around three core primitives. Read takes any URL and returns clean, LLM ready markdown. JavaScript rendering, anti bot bypass, proxy rotation, and content extraction all happen automatically. Crawl extends this across entire domains with configurable depth, URL pattern filtering, and structured output. Browse gives you full cloud browser sessions with CDP (Chrome DevTools Protocol) compatibility, meaning your existing Playwright and Puppeteer scripts connect and work without modification.

At the core of Reader's content conversion is Supermarkdown, an HTML to markdown engine built from scratch in Rust. It performs a single pass O(n) DOM traversal and converts a typical webpage in under 5 milliseconds. This is 10 to 50 times faster than JavaScript based converters like Turndown.js.

Reader offers 1,000 free pages per month on the managed platform with no credit card required.

## Browser Automation

This is the most significant difference between the two platforms.

ScrapingBee offers JavaScript scenarios that execute before page content is extracted. You can click elements, scroll pages, type into input fields, wait for selectors, and run custom JavaScript. These are useful for interacting with dynamic pages, dismissing popups, or triggering lazy loaded content. However, JavaScript scenarios are stateless. Each request creates a fresh browser context, executes the scenarios, extracts the content, and tears down. There are no persistent browser sessions. You cannot connect external automation tools like Playwright or Puppeteer.

Reader takes a different approach by offering full cloud browser sessions as a core primitive. When you create a browser session through the API, you get back a CDP endpoint. Any tool that supports the Chrome DevTools Protocol can connect to it. Playwright, Puppeteer, and Selenium all work natively because they all speak CDP.

```javascript
import { ReaderClient } from "@vakra-dev/reader-js";
import { chromium } from "playwright";

const reader = new ReaderClient({ apiKey: "rdr_your_key" });
const session = await reader.sessions.create({ maxDurationMs: 300000 });

const browser = await chromium.connectOverCDP(session.wsEndpoint);
const page = browser.contexts()[0].pages()[0];
await page.goto("https://example.com/dashboard");
await page.fill("#username", "user@example.com");
await page.click("#submit");
```

```python
from reader_py import ReaderClient
from playwright.sync_api import sync_playwright

client = ReaderClient(api_key="rdr_your_key")
session = client.sessions.create(max_duration_ms=300000)

with sync_playwright() as p:
    browser = p.chromium.connect_over_cdp(session.ws_endpoint)
    page = browser.contexts[0].pages[0]
    page.goto("https://example.com/dashboard")
```

This means you can log into a vendor portal, navigate through multiple authenticated pages, fill out forms, download files, and maintain session state across many interactions. The browser session persists for as long as you need it. Anti detection features including browser fingerprint generation, identity randomization, and proxy rotation are built into the browser sessions.

For teams that need to automate authenticated workflows (logging into client dashboards, navigating internal tools, interacting with platforms that have no API), Reader's browser sessions are a capability that ScrapingBee does not offer. For teams that just need to click a cookie banner before scraping a page, ScrapingBee's JavaScript scenarios work fine.

## Open Source and Self Hosting

ScrapingBee is fully closed source. There is no public GitHub repository for the product. There is no self hosting option. All usage goes through ScrapingBee's managed API.

Reader is fully open source under the Apache 2.0 license. The entire platform is on GitHub: the scraping engine, crawling infrastructure, browser pool management, anti bot features, the Supermarkdown conversion engine, and the cloud platform. You can clone the repository, deploy it on your own servers, inspect every line of code, and modify it to fit your needs.

The Apache 2.0 license is permissive. There are no restrictions on commercial use, no copyleft requirements, and no obligation to open source your own code if you modify or integrate Reader. This is a meaningful difference for teams that need to run scraping infrastructure inside their own network, operate in regulated environments where data cannot leave their systems, or want full control over every component of their scraping stack.

## Output Quality and Format

ScrapingBee returns HTML by default. You get the rendered page source, and it is up to you to parse and extract the content you need. ScrapingBee does offer an extract rules system using CSS selectors and XPath to pull specific elements, and the AI Query feature can extract structured data using natural language. But the default output is HTML.

Reader returns clean markdown by default. Every scrape passes through Supermarkdown, the Rust based conversion engine that strips navigation, ads, scripts, footers, cookie banners, and boilerplate. What comes back is clean markdown with document structure preserved: headings, paragraphs, lists, links, and tables intact.

For LLM pipelines, this distinction matters. Raw HTML wastes tokens on markup, navigation elements, and scripts that have nothing to do with the actual content. Clean markdown preserves the semantic structure of the page while reducing token count significantly. If you are building RAG pipelines, feeding content to language models, or processing web data at scale, markdown first output means less preprocessing and better results.

### Reader SDK Example

```python
from reader_py import ReaderClient

client = ReaderClient(api_key="rdr_your_key")
result = client.read(url="https://example.com")
print(result.data.markdown)
```

import { ReaderClient } from "@vakra-dev/reader-js";

const reader = new ReaderClient({ apiKey: "rdr_your_key" });

## Anti Bot and Success Rates

ScrapingBee provides proxy rotation across datacenter, premium, and stealth proxy tiers. JavaScript rendering handles pages that require browser execution. The platform has been handling anti bot challenges since 2019 and has significant operational experience.

In the Scrapeway independent benchmark from June 2026, which tested 8 scraping APIs across 12 target websites with over 1,000 requests each, ScrapingBee scored 39% overall success, ranking 6th out of 8 APIs tested. It achieved a fast average response time of 2.8 seconds. Notable gaps included 0% success on several heavily protected sites in earlier benchmark rounds.

Reader includes datacenter and residential proxy pools for IP reputation management. Browser sessions include browser fingerprint generation, identity randomization, and proxy rotation for anti detection. Reader does not yet have independent benchmark data published, and we want to be transparent about that. Anti bot performance varies significantly by target site, and we recommend testing with your actual URLs on both platforms.

## Integrations and Ecosystem

ScrapingBee has a mature integration ecosystem. Beyond the Python and JavaScript SDKs, it integrates with n8n and Make for no code workflows. The dedicated site APIs (Google, Amazon, Walmart, YouTube, ChatGPT) are unique to ScrapingBee and not something Reader or most other tools offer. An MCP server exposes these tools to AI coding assistants.

Reader offers SDKs for JavaScript and Python, a REST API, and an MCP server. LangChain and LlamaIndex work through Reader's SDK. The integration surface is growing but is not as broad as ScrapingBee's today, particularly around no code tools and dedicated site APIs.

If you specifically need Google SERP data, Amazon product data, or Walmart listings through a purpose built API, ScrapingBee has dedicated endpoints that Reader does not have.

## When to Pick Each Tool

### Choose ScrapingBee if:

You need dedicated, purpose built APIs for Google, Amazon, Walmart, YouTube, or ChatGPT. You want a fully managed service with no infrastructure to maintain and extensive operational track record. Your use case does not require persistent browser sessions or CDP access. You prefer a closed source platform with commercial support.

### Choose Reader if:

You need browser automation with full CDP access for Playwright and Puppeteer scripts. You want an open source platform you can self host, inspect, and modify under the Apache 2.0 license. You need markdown first output optimized for LLM pipelines without additional preprocessing. You operate in a regulated environment where data must stay on your infrastructure. You want to build on top of a platform you can fully control rather than depend on a managed service.

## Conclusion

ScrapingBee and Reader solve the same core problem from different directions. ScrapingBee is a mature, fully managed API with dedicated endpoints for specific platforms and years of operational experience. Reader is an open source platform that gives you full control, persistent browser sessions, and markdown first output designed for the AI era.

If you need Google, Amazon, or Walmart data through purpose built APIs, ScrapingBee is the more direct path. If you need open source licensing, browser automation with CDP, or self hosting on your own infrastructure, Reader is built for those requirements.

Both offer free tiers to test. Try them with your actual URLs and let the output quality and developer experience decide.
