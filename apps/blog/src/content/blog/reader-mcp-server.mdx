MCP (Model Context Protocol) is an open standard from Anthropic that connects AI applications to external tools. Think of it like USB for AI: a standard interface that lets any compatible AI tool use any compatible server.

Reader's MCP server gives AI agents the ability to scrape web pages, crawl entire sites, extract structured data, and create browser sessions. Once connected, your AI tool can fetch live web data without you writing any scraping code.

This guide shows how to set it up in Claude Code, Cursor, and other MCP-compatible tools.

## What Reader's MCP Server Exposes

The `@vakra-dev/reader-mcp` package exposes these tools to AI agents:

| Tool | What It Does |
|------|-------------|
| `reader_scrape` | Scrape a single URL, return clean markdown |
| `reader_batch_scrape` | Scrape multiple URLs as an async batch job |
| `reader_crawl` | Crawl a website, discover and scrape linked pages |
| `reader_discover` | Discover URLs on a site without scraping content |
| `reader_extract` | Scrape + extract structured data using AI |
| `reader_job_status` | Check status of async batch and crawl jobs |
| `reader_session_create` | Create a cloud browser session with CDP access |
| `reader_credits` | Check credit balance and usage |

Every tool that returns content gives the agent clean markdown. No HTML parsing needed on the agent's side.

## Setup in Claude Code

One command to install:

```bash
claude mcp add --env READER_API_KEY=rdr_your_key --transport stdio reader \
  -- npx -y @vakra-dev/reader-mcp
```

That is it. Claude Code will now have access to all Reader tools. You can verify by asking Claude to scrape a page:

> "Scrape https://docs.anthropic.com and summarize the key concepts"

Claude will call `reader_scrape`, get back clean markdown, and summarize it.

### What you can do with it

**Research a topic from live web data:**

> "Crawl the Reader documentation at docs.reader.dev and explain how the crawl API works"

Claude calls `reader_crawl` with the docs URL, gets markdown for every page, and synthesizes an answer from the actual documentation.

**Extract structured data:**

> "Go to this product page and extract the name, description, and key features as JSON"

Claude calls `reader_extract` with a schema and returns structured data.

**Create a browser session for complex interactions:**

> "Create a browser session and navigate to the dashboard to check the latest metrics"

Claude calls `reader_session_create` and gets a CDP URL it can use for browser automation.

## Setup in Cursor

Create `.cursor/mcp.json` in your project root:

```json
{
  "mcpServers": {
    "reader": {
      "command": "npx",
      "args": ["-y", "@vakra-dev/reader-mcp"],
      "env": {
        "READER_API_KEY": "rdr_your_key"
      }
    }
  }
}
```

Restart Cursor, and the Reader tools will be available to the AI assistant. You can also place this file at `~/.cursor/mcp.json` for global access across all projects.

## Setup in VS Code, Windsurf, and Other Editors

The configuration is the same JSON format across most MCP-compatible editors. Create an `mcp.json` file (location varies by editor) with the server configuration shown above.

For **Claude Desktop**, add the server to `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "reader": {
      "command": "npx",
      "args": ["-y", "@vakra-dev/reader-mcp"],
      "env": {
        "READER_API_KEY": "rdr_your_key"
      }
    }
  }
}
```

The server runs as a local stdio process. It communicates with the AI tool over JSON-RPC, and all API calls go through Reader's servers. Your API key is stored locally and never shared with the AI tool's cloud service.

## How It Compares to Other Scraping MCP Servers

Several [web scraping MCP servers](/blog/best-web-scraping-api) exist. Here is how they compare:

| MCP Server | Tools | Markdown Output | Browser Sessions | Crawl Support |
|-----------|-------|----------------|-----------------|--------------|
| Reader MCP | 8 | Yes (default) | Yes (CDP) | Yes |
| Firecrawl MCP | 11 | Yes (default) | Yes (Interact) | Yes |
| Playwright MCP | Browser automation | No (raw DOM) | Yes | No |
| Fetch MCP (reference) | 1 (fetch URL) | No | No | No |

Reader and [Firecrawl](/blog/reader-vs-firecrawl) MCP servers are the most capable for AI workflows. Reader's advantage is that the markdown output comes from [Supermarkdown](/blog/introducing-supermarkdown) (Rust engine), and browser sessions provide direct CDP access for Playwright and Puppeteer compatibility.

The reference Fetch MCP server (included in the official MCP servers repository) only fetches URLs without JavaScript rendering or content extraction. It is a starting point, not a production solution.

## Practical Examples

### Build a competitive analysis report

Ask your AI agent:

> "Scrape the landing pages of Firecrawl, ScrapingBee, and ZenRows. Compare their positioning, features, and messaging. Create a competitive analysis report."

The agent calls `reader_scrape` three times, gets clean markdown for each landing page, and produces a structured comparison.

### Index documentation for a knowledge base

> "Crawl all pages under docs.example.com (max 50 pages, depth 3) and save each page as a markdown file in the /docs folder"

The agent calls `reader_crawl`, polls the job status, and writes each page's markdown to a file. You now have a local copy of the documentation in a format you can search, index, or feed into a [RAG pipeline](/blog/scrape-website-to-markdown).

### Monitor a webpage for changes

> "Scrape this pricing page and compare it with the version I saved last week"

The agent calls `reader_scrape`, gets the current markdown, and diffs it against the saved version.
