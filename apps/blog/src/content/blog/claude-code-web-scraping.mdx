Claude Code cannot access the web by default. With Reader's MCP server, you can give it the ability to scrape any URL, crawl entire sites, extract structured data, and create browser sessions, all from within your terminal session. One install command, nine tools, full web access.

## What Reader MCP Gives Claude Code

Reader's MCP server (`@vakra-dev/reader-mcp`) exposes nine tools that Claude Code can call during any conversation.

**reader_scrape** takes a URL and returns clean, LLM ready markdown. JavaScript rendering, anti bot bypass, and content extraction happen automatically. This is the tool Claude Code uses most: "scrape this page and summarize it" or "read the documentation at this URL."

**reader_batch_scrape** processes up to 1,000 URLs in parallel. Useful when Claude Code needs to gather information from multiple sources: "scrape these 10 competitor pages and compare their feature lists."

**reader_crawl** discovers and scrapes pages across an entire domain. Set depth and page limits, and get back clean markdown for every discovered page. "Crawl the React documentation and create a quick reference guide."

**reader_discover** finds all URLs on a site without scraping them. Costs 1 credit flat regardless of how many URLs are found. Useful for understanding a site's structure before deciding what to crawl.

**reader_extract** scrapes a page and extracts structured data based on a JSON schema or natural language description. "Extract the product name, price, and availability from this page as JSON."

**reader_session_create** creates a browser session with a CDP WebSocket URL. Claude Code can then automate browser interactions: login flows, form filling, navigation. The session persists for as long as you need it.

**reader_job_status** checks the status of async jobs (batch scrapes and crawls).

**reader_cancel_job** cancels a running async job.

**reader_credits** checks your remaining credit balance.

## Installation

One command in your terminal:

```bash
claude mcp add reader -- npx -y @vakra-dev/reader-mcp
```

Set your API key as an environment variable:

```bash
export READER_API_KEY=rdr_your_key
```

Or pass it directly during setup:

```bash
claude mcp add reader --env READER_API_KEY=rdr_your_key -- npx -y @vakra-dev/reader-mcp
```

Verify the installation:

```bash
claude mcp list
```

You should see `reader` listed with its nine tools.

For team projects, add Reader MCP to your project's `.mcp.json` file so everyone on the team gets web access automatically:

```json
{
  "mcpServers": {
    "reader": {
      "command": "npx",
      "args": ["-y", "@vakra-dev/reader-mcp"],
      "env": {
        "READER_API_KEY": "rdr_your_key"
      }
    }
  }
}
```

Commit this file to your repository. Anyone who clones the project and runs Claude Code gets Reader's web tools automatically.

## Scraping a Page for Context

The most common use case: you need information from a web page during development.

**You:** "Scrape https://docs.stripe.com/api/charges and tell me what parameters the create charge endpoint accepts."

Claude Code calls `reader_scrape`, gets the clean markdown content of the Stripe API documentation, and summarizes the parameters directly in your terminal. No browser tab switching, no copy pasting, no manual extraction.

**You:** "Read the changelog at https://github.com/vercel/next.js/releases and tell me what changed in the latest version."

Claude Code scrapes the releases page, parses the markdown, and gives you a concise summary of the latest changes. This is useful when you are debugging a breaking change or evaluating whether to upgrade a dependency.

## Crawling Documentation

When you need to understand an entire documentation site, not just one page.

**You:** "Crawl https://docs.reader.dev with max depth 2 and summarize all the API endpoints available."

Claude Code calls `reader_crawl`, which discovers and scrapes every page within 2 levels of the root URL. It then processes all the returned markdown and produces a structured summary. For a documentation site with 30 pages, this takes about a minute and gives you a complete overview without reading each page manually.

**You:** "Crawl our competitor's documentation site and compare their feature set with ours."

Claude Code crawls the site, extracts the relevant content, and produces a comparison. This is competitive analysis that would take a human an hour, done in a minute.

## Extracting Structured Data

When you need specific fields from a page, not the full content.

**You:** "Extract the company name, number of employees, and headquarters location from https://example.com/about as JSON."

Claude Code calls `reader_extract` with a schema that defines the fields you want. The response is typed JSON:

```json
{
  "company_name": "Example Corp",
  "employees": 250,
  "headquarters": "San Francisco, CA"
}
```

You can also use natural language instead of a formal schema: "Extract all the pricing tiers and what each includes." Reader's extract tool handles both approaches.

## Browser Sessions

For pages that require authentication or interaction before the content is accessible.

**You:** "Create a browser session so I can test the login flow on our staging environment."

Claude Code calls `reader_session_create` and gets back a CDP WebSocket URL. From there, it can automate browser interactions: navigate to the login page, fill in credentials, submit the form, and verify the result. The session stays active for follow up commands.

This is useful for testing authenticated workflows, scraping pages behind login walls, and automating repetitive browser tasks during development.

## Installation in Other AI Tools

Reader MCP is not limited to Claude Code. It works with any MCP compatible client.

**Claude Desktop** (macOS):
Add to `~/Library/Application Support/Claude/claude_desktop_config.json`:
```json
{
  "mcpServers": {
    "reader": {
      "command": "npx",
      "args": ["-y", "@vakra-dev/reader-mcp"],
      "env": { "READER_API_KEY": "rdr_your_key" }
    }
  }
}
```

**Cursor:**
Add through Cursor Settings > MCP with the same command and arguments.

**VS Code:**
Configure through the MCP extension settings with the same JSON structure.

**Windsurf, Codex, OpenCode:**
All follow the same pattern. See the [Reader MCP documentation](https://github.com/vakra-dev/reader-mcp) for specific paths for each client.
