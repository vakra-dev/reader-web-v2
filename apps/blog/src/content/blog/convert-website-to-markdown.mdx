Converting a website to markdown sounds simple. Fetch the HTML, strip the tags, done. In practice, it is one of those problems that gets harder the deeper you go.

Raw HTML from a modern web page is full of navigation bars, tracking scripts, cookie banners, inline styles, and SVG icons. If you are feeding this into an LLM, you are wasting 70-90% of your tokens on content that adds zero value. Clean markdown preserves the structure (headings, lists, tables, code blocks) without the noise.

This guide covers four approaches, from simple libraries to production APIs, so you can pick the right one for your use case.

## The Problem with Raw HTML

A typical web page contains far more markup than actual content. Here is what a single paragraph looks like in HTML versus markdown:

**Raw HTML (45 tokens):**

```html
<div class="article-content mt-8 prose prose-lg mx-auto">
  <p class="text-gray-700 leading-relaxed mb-4">
    Machine learning models require <strong class="font-bold">clean data</strong>
    to produce accurate results.
  </p>
</div>
```

**Clean markdown (12 tokens):**

```markdown
Machine learning models require **clean data** to produce accurate results.
```

That is a 73% reduction on a single paragraph. On a full page with navigation, footers, and scripts, the reduction is typically 80-95%. For an LLM processing hundreds of pages in a [RAG pipeline](/blog/scrape-website-to-markdown), this difference adds up fast.

## Option 1: Turndown.js (JavaScript)

[Turndown.js](https://github.com/mixmark-io/turndown) is the most popular HTML-to-markdown library in JavaScript, with over 11,000 GitHub stars. It converts HTML strings to markdown using a rule-based system.

Install it with npm:

```bash
npm install turndown turndown-plugin-gfm
```

Basic conversion looks like this:

```javascript
const TurndownService = require("turndown");
const { gfm } = require("turndown-plugin-gfm");

const turndown = new TurndownService({
  headingStyle: "atx",
  codeBlockStyle: "fenced",
});

// Add GitHub Flavored Markdown support (tables, strikethrough)
turndown.use(gfm);

const html = `
  <h1>Getting Started</h1>
  <p>Install the package with <code>npm install reader</code></p>
  <ul>
    <li>Fast conversion</li>
    <li>GFM tables supported</li>
  </ul>
`;

const markdown = turndown.turndown(html);
console.log(markdown);
```

Output:

```markdown
# Getting Started

Install the package with `npm install reader`

- Fast conversion
- GFM tables supported
```

Turndown works well for clean HTML fragments. But it has two limitations that matter for web scraping.

First, it does not extract main content. If you pass an entire web page, you get the navigation, sidebar, footer, and cookie banner converted to markdown along with the article. You need a separate content extraction step.

Second, it does not handle pages rendered by JavaScript. If the page uses React, Next.js, or any client-side framework, the HTML you fetch with a simple HTTP request will be mostly empty `<div>` containers.

## Option 2: html2text (Python)

For Python developers, [html2text](https://pypi.org/project/html2text/) converts HTML to readable markdown. It was originally written by Aaron Swartz.

```bash
pip install html2text
```

```python
import html2text

h = html2text.HTML2Text()
h.body_width = 0  # Don't wrap lines
h.ignore_links = False
h.ignore_images = False

html = """
<h2>API Reference</h2>
<p>Send a <strong>POST</strong> request to the <code>/read</code> endpoint.</p>
<table>
  <tr><th>Parameter</th><th>Type</th></tr>
  <tr><td>url</td><td>string</td></tr>
  <tr><td>formats</td><td>array</td></tr>
</table>
"""

print(h.handle(html))
```

Output:

```markdown
## API Reference

Send a **POST** request to the `/read` endpoint.

Parameter | Type
---|---
url | string
formats | array
```

html2text is lightweight and handles basic conversions well. Like Turndown, it converts whatever HTML you give it, including navigation and boilerplate. It also does not render JavaScript.

## Option 3: Readability + Turndown (Two-Step)

A common pattern is to use [Readability.js](https://github.com/mozilla/readability) (Mozilla's content extraction library, used in Firefox Reader View) to extract the main content first, then convert it with Turndown.

```javascript
const { Readability } = require("@mozilla/readability");
const { JSDOM } = require("jsdom");
const TurndownService = require("turndown");
const { gfm } = require("turndown-plugin-gfm");

// Step 1: Fetch the page
const response = await fetch("https://example.com/blog/post");
const html = await response.text();

// Step 2: Extract main content with Readability
const dom = new JSDOM(html, { url: "https://example.com/blog/post" });
const article = new Readability(dom.window.document).parse();

// Step 3: Convert to markdown
const turndown = new TurndownService({ headingStyle: "atx" });
turndown.use(gfm);
const markdown = turndown.turndown(article.content);

console.log(article.title);
console.log(markdown);
```

This approach is better than either tool alone. Readability strips navigation, ads, and sidebars. Turndown then converts the clean HTML to markdown.

But it still has gaps. Readability only works on static HTML. Pages that load content via JavaScript will return incomplete or empty results. You also need to handle fetching, error handling, retries, and rate limiting yourself. And some pages will not have a clear "main content" block, causing Readability to extract the wrong section.

## Option 4: Reader API (One Call)

If you need to convert web pages to markdown reliably, including pages rendered by JavaScript and pages behind anti-bot protection, [Reader](https://docs.reader.dev) handles the full pipeline in a single API call.

Reader renders the page in a headless browser, extracts the main content, and converts it to markdown using [Supermarkdown](/blog/introducing-supermarkdown), a Rust engine built specifically for this conversion.

**Python:**

```python
from reader_py import ReaderClient

client = ReaderClient(api_key="rdr_your_api_key")
result = client.read(url="https://example.com/blog/post")

print(result.data.markdown)
```

**JavaScript:**

```javascript
import { ReaderClient } from "@vakra-dev/reader-js";

const reader = new ReaderClient({ apiKey: "rdr_your_api_key" });
const result = await reader.read({
  url: "https://example.com/blog/post",
});

console.log(result.data.markdown);
```

**cURL:**

```bash
curl -X POST https://api.reader.dev/v1/read \
  -H "Content-Type: application/json" \
  -H "x-api-key: rdr_your_api_key" \
  -d '{"url": "https://example.com/blog/post"}'
```

The output is clean markdown with headings, lists, tables, and code blocks preserved. No navigation, no ads, no cookie banners.

Reader handles several problems that the library approach does not:

- **JavaScript rendering.** Pages built with React, Vue, or Next.js are fully rendered before extraction.
- **Anti-bot bypass.** Sites protected by Cloudflare, CAPTCHAs, and other bot detection are handled automatically.
- **Content extraction.** Main content is extracted and boilerplate is stripped without needing Readability.
- **Edge cases.** Complex tables, nested lists, code blocks with language detection, and malformed HTML are all handled by the Supermarkdown engine.

## Inside Supermarkdown: The Rust Engine That Powers the Conversion

The markdown conversion in Reader is powered by [Supermarkdown](https://supermarkdown.dev), an open-source Rust library built from scratch for this problem. It is not a port of Turndown or any existing converter. It is a ground-up implementation designed for speed, correctness, and the edge cases that real web pages throw at you.

You can use Supermarkdown standalone, without Reader. It is available as a [Rust crate](https://crates.io/crates/supermarkdown), an [npm package](https://www.npmjs.com/package/@vakra-dev/supermarkdown) with native bindings, and a CLI tool.

### Why Build a New Converter?

Existing converters struggle with real web content. Turndown.js uses regex-based escaping that over-escapes in many cases. html2text produces plain text that loses structural information. Pandoc converts everything including navigation and boilerplate. None of them handle the edge cases well: tables with alignment, code blocks that contain backticks, deeply nested lists, or malformed HTML from the wild web.

Supermarkdown was built to handle all of these correctly and fast.

### How It Works: Three Passes, O(n) Complexity

Most HTML-to-markdown converters are slower than they need to be. The typical approach for nested lists is to walk up the DOM tree for every list item to figure out the indentation level. That makes the algorithm O(n²) for documents with many list items.

Supermarkdown avoids this with a pre-computation pass. It traverses the DOM once, computes all the metadata (list prefixes, indentation levels, skip flags from CSS selectors), and stores it in a hash map. The actual conversion pass then does O(1) lookups instead of tree walks.

The full pipeline is:

1. **Parse** the HTML using html5ever, an HTML5 spec-compliant parser from the Servo project. This handles malformed HTML the same way browsers do.
2. **Precompute** all node metadata in a single depth-first traversal. List indentation, ordered list counters, CSS selector matches, everything computed once.
3. **Convert** each node to markdown using modular rules, with O(1) metadata lookups.
4. **Postprocess** the output in a single pass: collapse extra newlines, escape markdown special characters, trim trailing whitespace.

Three linear passes instead of quadratic traversals. The result is that Supermarkdown processes a typical web page in under 1ms.

### What It Handles That Others Miss

**Table alignment.** Supermarkdown reads the `align` attribute and `text-align` CSS style on table cells and generates proper GFM alignment syntax (`:---`, `:---:`, `---:`).

**Code language detection.** When converting `<pre><code>` blocks, it checks for `language-*`, `lang-*`, `highlight-*`, and `hljs-*` class patterns to produce fenced code blocks with the correct language identifier. It also strips line number gutters that syntax highlighters inject.

**Dynamic fence calculation.** If a code block contains triple backticks, Supermarkdown automatically uses four backtick fences. This prevents broken output that most converters produce.

**Ordered list start values.** HTML supports `<ol start="5">`. Supermarkdown respects this and starts the list at the correct number.

**URL handling.** Spaces and parentheses in URLs are encoded. Relative URLs are resolved against a base URL if provided. Base64 data URIs in images are skipped since they have no meaningful markdown representation.

**Selector-based filtering.** You can pass CSS selectors to exclude or include specific elements. This lets you strip navigation, sidebars, or ad containers before conversion, without needing a separate content extraction library.

### Using Supermarkdown Standalone

**Node.js:**

```javascript
import { convert } from "@vakra-dev/supermarkdown";

const html = `
  <h1>Getting Started</h1>
  <p>Install with <code>npm install reader</code></p>
  <table>
    <tr><th>Feature</th><th align="center">Status</th></tr>
    <tr><td>Tables</td><td align="center">Supported</td></tr>
    <tr><td>Code blocks</td><td align="center">Supported</td></tr>
  </table>
`;

const markdown = convert(html, {
  headingStyle: "atx",
  bulletMarker: "-",
  excludeSelectors: ["nav", "footer", ".ad-banner"],
});

console.log(markdown);
```

Output:

```markdown
# Getting Started

Install with `npm install reader`

| Feature | Status |
| --- | :---: |
| Tables | Supported |
| Code blocks | Supported |
```

**Rust:**

```rust
use supermarkdown::{convert, Options};

let html = "<h1>Hello</h1><p>World</p>";
let options = Options::default();
let markdown = convert(html, &options);
```

**CLI:**

```bash
# Convert a file
supermarkdown page.html > output.md

# Pipe from curl
curl -s https://example.com | supermarkdown

# Exclude elements
supermarkdown --exclude "nav,footer,.sidebar" page.html
```

Supermarkdown ships pre-built native binaries for Linux (x86_64, ARM64), macOS (Intel, Apple Silicon), and Windows. No compilation step needed when you install via npm.

Visit [supermarkdown.dev](https://supermarkdown.dev) for the full documentation.

## When to Use Which Approach

| Approach | Best for | Handles JS? | Content extraction? | Speed |
|----------|----------|-------------|-------------------|-------|
| Turndown.js | Clean HTML fragments you already have | No | No | Fast (JS) |
| html2text | Quick Python scripts, simple pages | No | No | Fast (Python) |
| Readability + Turndown | Static pages with clear article content | No | Yes | Fast (JS) |
| Supermarkdown | High-volume conversion, Rust/Node.js projects | No | Via selectors | Very fast (Rust native) |
| Reader API | Production use, any URL, JavaScript pages | Yes | Yes | Includes network time |

If you are converting HTML strings you already have, Supermarkdown gives you the best output quality and speed. If you need to fetch live web pages at scale, including pages that use JavaScript or anti-bot protection, Reader handles [the full pipeline](/blog/best-web-scraping-api) and uses Supermarkdown under the hood.

## Common Conversion Pitfalls (and How Supermarkdown Handles Them)

Every HTML-to-markdown converter runs into these problems. Here is how they typically fail and how [Supermarkdown](https://supermarkdown.dev) handles each one.

**Tables with colspan or rowspan.** Markdown tables require uniform column counts. HTML tables with merged cells have no clean equivalent. Most tools break the layout or dump raw HTML. Supermarkdown places merged cell content in the first cell and preserves alignment attributes, producing a valid GFM table that renders correctly.

**Deeply nested lists.** Mixed ordered and unordered lists nested three or more levels deep break most converters. The indentation math is hard to get right. Supermarkdown pre-computes all indentation levels in a single pass, so even 10+ levels of nesting render correctly without performance degradation.

**Code blocks containing backticks.** If your content has code examples that themselves contain triple backticks, the converter needs to use a longer fence. Most tools do not handle this. Supermarkdown dynamically calculates the required fence length and uses four or more backticks when needed.

**Lazy loaded images.** Many sites use `data-src` instead of `src` for images. Converters that only check `src` will miss these. Reader's headless browser renders the page fully before passing the HTML to Supermarkdown, so all lazy loaded content is present in the DOM.

**Malformed HTML.** The real web is full of unclosed tags, mismatched nesting, and invalid attributes. Regex-based converters break on these. Supermarkdown uses html5ever, an HTML5 spec-compliant parser from the Servo project that recovers from malformed markup the same way browsers do.

## Conclusion

Converting websites to markdown is straightforward for simple cases and complex for real-world pages. Turndown.js and html2text work for clean HTML you already have. For better quality and speed, [Supermarkdown](https://supermarkdown.dev) handles the conversion in Rust with correct output for tables, nested lists, code blocks, and malformed HTML. For live web pages that need JavaScript rendering and anti-bot bypass, Reader uses Supermarkdown under the hood and handles the full pipeline in one API call.

Check the [Reader documentation](https://docs.reader.dev) to start converting URLs to markdown, or install [Supermarkdown](https://supermarkdown.dev) directly if you already have HTML and just need fast, accurate conversion.
