Converting a website to clean markdown is one of the most common tasks in AI development. Web pages are built for browsers, full of navigation menus, advertising scripts, cookie banners, and tracking pixels. The actual content represents roughly 20% of the HTML. The other 80% is noise that wastes tokens and degrades LLM performance.

This guide covers six methods for converting web pages to markdown, from quick JavaScript libraries to a purpose built Rust engine, and helps you pick the right one for your use case.

## Why Markdown Instead of HTML for LLMs

The token efficiency difference between HTML and markdown is significant and well documented.

A typical 3,000 word article uses roughly 8,000 tokens as HTML but only 2,800 tokens as clean markdown. That is a 67% reduction for identical semantic content. For real world web pages with navigation, ads, and scripts, the reduction reaches 87% because markdown strips everything that is not actual content.

Academic research supports this. The TQA Bench study (arXiv 2411.19504) found that HTML requires nearly three times more tokens than lightweight formats like markdown for tabular data serialization. At 64K scale, HTML databases exceed 128K tokens, pushing past the context limits of most models.

The practical impact is threefold. Lower token count means lower API costs, especially at scale. More content fits within a model's context window, enabling richer retrieval. And LLMs parse markdown more reliably than HTML because the signal to noise ratio is dramatically higher.

Beyond token efficiency, markdown preserves semantic structure. Headings map to document hierarchy. Lists stay as lists. Tables remain tabular. Links are preserved. The content is readable by both humans and machines without any rendering engine.

## The Two Step Problem

Converting a webpage to markdown is actually two separate problems that require different tools.

The first problem is content extraction: identifying and isolating the main content from navigation, headers, footers, sidebars, advertisements, and cookie banners. This is a classification problem. The tool needs to understand which part of the page is the actual article or content and which parts are chrome.

The second problem is structural conversion: transforming HTML tags into markdown syntax. An `<h2>` becomes `##`. A `<ul>` becomes a bulleted list. A `<table>` becomes a GFM table. This is a transformation problem that requires correct handling of nesting, indentation, and edge cases.

Different tools excel at each step. Readability.js is excellent at content extraction but does not convert to markdown. Turndown.js is excellent at structural conversion but converts everything you give it, including navigation and ads. The best results come from combining both steps, or using a tool that handles both in a single pass.

## Method 1: Turndown.js

Turndown.js is the most widely used HTML to markdown converter in the JavaScript ecosystem. It has over 11,000 GitHub stars, more than 3 million weekly npm downloads, and is licensed under MIT. It powers Jina Reader's conversion pipeline and countless web clippers and content management tools.

Turndown works in both Node.js and browser environments. It is plugin extensible, with GFM support (tables, strikethrough, task lists) available through the turndown-plugin-gfm package.

```javascript
const TurndownService = require('turndown');
const turndownPluginGfm = require('turndown-plugin-gfm');

const turndownService = new TurndownService();
turndownService.use(turndownPluginGfm.gfm);

const markdown = turndownService.turndown('<h1>Hello</h1><p>World</p>');
console.log(markdown);
// # Hello
//
// World
```

Turndown's limitation is that it converts whatever HTML you give it. It does not extract main content or strip boilerplate. If you pass it a full web page, the output includes navigation menus, footer links, cookie banners, and everything else in the DOM. It also does not recover from malformed HTML. If the input has unclosed tags or incorrect nesting, the output may be garbled.

For clean, well structured HTML fragments, Turndown produces excellent results. For full web pages, you need a content extraction step before conversion.

## Method 2: Python (html2text and markdownify)

Python offers two popular options for HTML to markdown conversion.

**html2text** was originally created by Aaron Swartz. It produces readable plaintext with markdown style formatting. It is lightweight, fast, and good for quick conversions where perfect GFM compliance is not required.

```python
import html2text

converter = html2text.HTML2Text()
converter.body_width = 0  # Disable line wrapping

html = "<h1>Hello</h1><p>This is a <a href='https://example.com'>link</a></p>"
markdown = converter.handle(html)
print(markdown)
```

html2text has options for ignoring links, images, and tables. It is better suited for "make this readable" than "produce valid GFM."

**markdownify** offers more control and better handling of complex structures. It is MIT licensed, actively maintained, and handles nested lists and tables more accurately than html2text. Recent releases added definition list support and table header inference.

```python
from markdownify import markdownify as md

html = "<h1>Hello</h1><ul><li>Item 1<ul><li>Nested</li></ul></li></ul>"
markdown = md(html)
print(markdown)
```

Neither library handles JavaScript rendered pages. They work on static HTML strings only. If the page content loads dynamically through JavaScript (which is roughly 80% of the modern web), you need to render the page with a headless browser first and then pass the rendered HTML to the converter.

## Method 3: Pandoc

Pandoc is the universal document converter. It handles dozens of input and output formats, including HTML to GitHub Flavored Markdown via `pandoc -f html -t gfm`.

Pandoc has the best edge case handling of any converter. It correctly processes nested tables, definition lists, footnotes, and complex document structures that trip up other tools. If your HTML has unusual or deeply nested structures, Pandoc is the most likely to produce correct output.

The limitation is that Pandoc is a Haskell binary installed via system package managers, not a library you import into your application. This makes it impractical for serverless environments, browser based tools, or applications that need to bundle everything as a single deployment. It also converts the entire document, including navigation and boilerplate, because it has no concept of content extraction.

Pandoc is best for converting local HTML files or well structured document fragments, not for live web scraping.

## Method 4: Readability.js + Turndown

The two step pattern that solves both the content extraction and structural conversion problems.

Mozilla Readability (the engine behind Firefox Reader View) analyzes an HTML document, identifies the main article content, and strips everything else: navigation, ads, sidebars, footers, and boilerplate. Turndown then converts the cleaned HTML to markdown.

```javascript
const { JSDOM } = require('jsdom');
const { Readability } = require('@mozilla/readability');
const TurndownService = require('turndown');

const dom = new JSDOM(html, { url: pageUrl });
const article = new Readability(dom.window.document).parse();

const turndownService = new TurndownService();
const markdown = turndownService.turndown(article.content);
console.log(markdown);
```

This combination is what Jina Reader uses under the hood. It produces good results for article style content and blog posts. The limitation is that Readability is designed for articles specifically, not for arbitrary page types like product listings, documentation, or dashboards. It also requires two dependencies and is JavaScript only.

## Method 5: Supermarkdown (Rust)

Supermarkdown is an HTML to markdown conversion engine built from scratch in Rust, designed specifically for web scraping and LLM pipelines. It is available at [supermarkdown.dev](https://supermarkdown.dev) and open source under the MIT license.

### Architecture

Supermarkdown uses html5ever for HTML parsing, the same parser that Firefox uses. This provides browser grade error recovery, meaning malformed HTML (unclosed tags, incorrect nesting, CMS mangled markup) is handled correctly rather than causing crashes or garbled output.

The conversion uses a single pass O(n) DOM traversal. In one pass, it pre computes all metadata: list indices, CSS selector matches, heading levels, and code block nesting depths. A second pass converts the DOM to markdown using O(1) lookups against the pre computed metadata. There is no intermediate representation, no AST, and no multi pass transformation. HTML goes in, markdown comes out.

Rust's ownership model means zero garbage collector pauses and predictable latency. This matters for pipelines processing thousands of pages where consistent throughput is more important than peak speed.

### GFM Support

Supermarkdown produces full GitHub Flavored Markdown:

Tables with alignment detection. It reads the `align` attribute and `text-align` CSS property to set column alignment. The first row automatically becomes the header.

Fenced code blocks with language detection. It reads class patterns including `language-*`, `lang-*`, `highlight-*`, and `hljs-*` to identify the programming language. Line numbers from syntax highlighting are automatically stripped. Dynamic backtick fencing handles code that contains backticks by wrapping in more backticks.

Lists with correct nesting. Deeply nested lists preserve proper indentation. Ordered lists preserve the `start` attribute. Task lists (checkbox items) and definition lists (dt/dd elements) are both supported.

Links and URLs. Configurable inline or reference style. Relative URLs resolve to absolute via the `baseUrl` option. Spaces and parentheses in URLs are percent encoded automatically.

Details/summary elements, strikethrough, autolinks, horizontal rules, and blockquotes (including nested) are all handled.

### Content Filtering

Supermarkdown can extract content during conversion through CSS selector filtering:

```javascript
import { convert } from '@vakra-dev/supermarkdown';

const markdown = convert(html, {
  baseUrl: 'https://example.com',
  excludeSelectors: ['nav', '.sidebar', '.footer', '.cookie-banner', '.ad'],
  includeSelectors: ['article', 'main', '.content']
});
```

The `excludeSelectors` option skips elements matching those CSS selectors. The `includeSelectors` option processes only elements matching those selectors. This enables content extraction and structural conversion in a single pass, eliminating the need for a separate Readability step.

### Usage

**Node.js:**
```bash
npm install @vakra-dev/supermarkdown
```
```javascript
import { convert } from '@vakra-dev/supermarkdown';

const markdown = convert('<h1>Hello</h1><p>World</p>');
// # Hello\n\nWorld
```

**Rust:**
```bash
cargo add supermarkdown
```
```rust
use supermarkdown::{convert, Options};

let options = Options {
    base_url: Some("https://example.com".into()),
    ..Default::default()
};
let markdown = convert(html, Some(options));
```

**CLI:**
```bash
cargo install supermarkdown-cli

# Convert a file
supermarkdown input.html

# Pipe from curl
curl -s https://example.com | supermarkdown

# With base URL
supermarkdown --base-url https://example.com input.html
```

Supermarkdown also supports async conversion via `convertAsync` for large documents that should not block the event loop.

### Edge Case Handling

Real world web HTML is messy. Supermarkdown handles the cases that break other converters:

Colspan content is placed in the first cell because markdown has no colspan syntax. Nested tables are flattened for the same reason. Forms, iframes, video, and audio elements are skipped because they have no markdown equivalent. Empty elements are removed. These are all graceful degradations rather than crashes.

## Method 6: ReaderLM v2 (Neural Conversion)

ReaderLM v2 is a fundamentally different approach. Built by Jina AI, it is a 1.5 billion parameter language model (based on Qwen2.5 1.5B Instruct) that converts HTML to markdown using AI rather than rules.

It handles up to 512K combined input and output tokens, supports 29 languages, and achieves a ROUGE L score of 0.84 on main content extraction benchmarks. The model is Apache 2.0 licensed and available on HuggingFace. It remains available after Elastic completed its acquisition of Jina AI in October 2025.

The tradeoff is speed and cost. Neural conversion requires GPU inference (~67 tokens/s in, ~36 tokens/s out on a T4 GPU), making it orders of magnitude slower than rule based converters. But it handles ambiguous content better because it can reason about what constitutes the main content versus boilerplate, even on unusual page layouts.

ReaderLM v2 is best for pages where the content structure is unclear or inconsistent and rule based extractors struggle.

## Which Method to Use

For a quick conversion in a JavaScript project, use Turndown.js. It is the most popular, well documented, and plugin extensible.

For a quick conversion in Python, use markdownify. It handles nested lists and tables better than html2text.

For content extraction combined with conversion, use Readability.js plus Turndown in JavaScript, or Supermarkdown with CSS selector filtering in any environment.

For production pipelines that need speed, accuracy, and GFM compliance, use Supermarkdown. The Rust engine with single pass conversion and html5ever parsing handles the edge cases that break other converters.

For maximum edge case handling on local files, use Pandoc.

For ambiguous or inconsistent page structures, use ReaderLM v2.

For the full end to end pipeline (fetch, render JavaScript, extract content, convert to markdown), use Reader. It handles all of these steps in a single API call with Supermarkdown running under the hood.

```bash

  -H "Content-Type: application/json" \
  -d '{"url": "https://example.com"}'
```

## Conclusion

Converting web pages to clean markdown is a solved problem with multiple good options. The right choice depends on your language, your performance requirements, and how messy your HTML sources are.

For most developers building AI applications, the decision comes down to two paths. Use Supermarkdown as a library if you want the converter integrated into your own pipeline. Use Reader if you want the full end to end web scraping and conversion pipeline handled for you. Both are open source, both produce clean GFM output, and both handle the messy reality of web HTML.
