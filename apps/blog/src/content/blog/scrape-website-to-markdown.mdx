LLMs work best with clean, structured input. Feeding raw HTML into a language model wastes tokens on navigation menus, scripts, and markup that have nothing to do with the actual content. A 3,000 word article consumes roughly 8,000 tokens as HTML but only 2,800 as clean markdown. That is a 67% reduction with no loss of semantic information.

Scraping a website to markdown gives you content in a format that preserves document structure (headings, lists, tables, links) while stripping everything else. This guide shows how to do it with Reader, from a single page to an entire site.

## Scraping a Single Page

Reader's `/v1/read` endpoint takes a URL and returns clean markdown. JavaScript rendering, anti bot bypass, proxy rotation, and content extraction all happen automatically.

**Python:**
```python
from reader_py import ReaderClient

client = ReaderClient(api_key="rdr_your_key")
result = client.read(url="https://example.com/blog/post")

print(result.data.markdown)
print(result.data.metadata.title)
print(result.data.metadata.status_code)
```

**JavaScript:**
```javascript
import { ReaderClient } from '@vakra-dev/reader-js';

const reader = new ReaderClient({ apiKey: 'rdr_your_key' });
const result = await reader.read({ url: 'https://example.com/blog/post' });

console.log(result.data.markdown);
console.log(result.data.metadata.title);
```

**cURL:**
```bash
curl -X POST https://api.reader.dev/v1/read \
  -H "x-api-key: rdr_your_key" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://example.com/blog/post"}'
```

The response includes the clean markdown, the raw HTML (if requested), metadata (title, description, status code, duration, whether the result was cached), and optionally a screenshot.

The `onlyMainContent` parameter defaults to true, which strips navigation, footers, sidebars, and boilerplate automatically. Set it to false if you need the full page content.

## Scraping Multiple Pages

For batch scraping, pass multiple URLs in a single request. Reader processes them in parallel.

```python
from reader_py import ReaderClient

client = ReaderClient(api_key="rdr_your_key")

urls = [
    "https://example.com/blog/post-1",
    "https://example.com/blog/post-2",
    "https://example.com/blog/post-3",
    "https://example.com/blog/post-4",
    "https://example.com/blog/post-5",
]

result = client.read(urls=urls)

for page in result.data:
    print(f"{page.url}: {len(page.markdown)} chars")
```

Batch requests with multiple URLs return an async job (HTTP 201). The SDK handles polling automatically. You can scrape up to 1,000 URLs in a single batch. The `batchConcurrency` parameter (1 to 20) controls how many pages are fetched simultaneously.

## Crawling an Entire Site to Markdown

For full site crawling, add `maxDepth` and `maxPages` to trigger crawl mode. Reader discovers links via BFS (breadth first search), stays on the same domain, and scrapes every discovered page to markdown.

```python
from reader_py import ReaderClient

client = ReaderClient(api_key="rdr_your_key")

result = client.read(
    url="https://docs.example.com",
    max_depth=3,
    max_pages=100
)

for page in result.data:
    print(f"{page.url}")
    # Save to file, embed for RAG, process with LLM
    with open(f"output/{page.url.split('/')[-1]}.md", "w") as f:
        f.write(page.markdown)
```

Crawl configuration options include `includePatterns` and `excludePatterns` (regex arrays for URL filtering), `delayMs` (rate limiting between requests), and `scrape` (set to false for URL discovery only at 1 credit flat).

## Feeding Markdown into LLM Pipelines

Once you have clean markdown, the next step is chunking it for retrieval or processing.

### Chunking Strategy

For markdown content, the most effective approach is two level splitting. First split on headings to preserve document hierarchy, then split by size for embedding.

```python
from langchain.text_splitter import (
    MarkdownHeaderTextSplitter,
    RecursiveCharacterTextSplitter
)

# Step 1: Split on headings
headers_to_split_on = [
    ("#", "h1"),
    ("##", "h2"),
    ("###", "h3"),
]
md_splitter = MarkdownHeaderTextSplitter(
    headers_to_split_on=headers_to_split_on
)
md_docs = md_splitter.split_text(markdown_content)

# Step 2: Split by size
text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000,
    chunk_overlap=200
)
chunks = text_splitter.split_documents(md_docs)
```

This preserves heading hierarchy as metadata on each chunk, which improves retrieval quality because the retriever knows which section each chunk belongs to.

### Embedding and Storage

```python
from langchain_openai import OpenAIEmbeddings
from langchain_chroma import Chroma

embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vectorstore = Chroma.from_documents(chunks, embeddings)
```

### Querying

```python
from langchain_openai import ChatOpenAI
from langchain.chains import RetrievalQA

qa = RetrievalQA.from_chain_type(
    llm=ChatOpenAI(model="gpt-4.1-mini"),
    retriever=vectorstore.as_retriever(search_kwargs={"k": 5})
)

answer = qa.invoke("How do I configure authentication?")
print(answer["result"])
```

## Best Practices

**Use onlyMainContent: true.** This is the default and strips boilerplate automatically. Only disable it if you specifically need navigation or footer content.

**Chunk by headings first, then by size.** Markdown's explicit heading markers (`#`, `##`, `###`) make it ideal for semantic chunking. HTML does not have this advantage because structural markers are buried in tag attributes.

**Measure chunk size in tokens, not characters.** Use tiktoken to count tokens for your target model. A 1,000 character chunk might be 200 tokens or 400 tokens depending on the content.

**Cache aggressively.** Reader returns cached results at zero credit cost. If you are re processing the same URLs, the second request is free and instant.

**For large crawls, use async mode.** Crawls with more than a few pages run asynchronously. The SDK handles polling, but monitor job status for large crawls (100+ pages) to catch failures early.
